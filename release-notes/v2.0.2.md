### Highlights

**Revit 2023 and 2024 support:**

- **The bridge builds for Revit 2023 and 2024** (ports 5051-5059 and 5061-5069). `revit-cli configure setup` deploys into the 2023/2024 add-ins folders and instance discovery accepts them. The element-id compatibility layer keeps the 2024 API change in one class.

**Fixes:**

- **`create_wall --height` is applied.** The handler sets the wall height inside the transaction and echoes the value read back from the wall. An omitted `--height` keeps the wall type height; the schema no longer promises a 3000 default.
- **`undo --count` is honored.** The handler reads `count` (`steps` is still accepted). The response now reports `steps_posted` / `steps_requested` instead of `steps_executed`; update parsers keyed on the old name. Revit accepts one queued undo per call, so `undo --count 2` posts one and the message says so; repeat the command.
- **Units survive a rewritten command name.** `wall_create`, `elements.create_wall` and `wall_create@v1` convert and echo the same `units` as `create_wall`.
- **`--dry-run` before the command name is a usage error.** `revit-cli --dry-run create_wall ...` used to drop the flag and run the command for real; it now exits 1 before any bridge call.
- **`list --json` omits the API key.** The key stays in the registry file for authentication and no longer appears in the JSON output.
- **Schema cache cannot strand a stale list.** The client saves the cache list before its ETag and sends a stored ETag only when the list file exists, so a failed write no longer pins a stale list behind endless 304s.
- **Task outcome cannot flip after it ends.** Terminal transitions are atomic; a timed-out task no longer becomes completed after its command committed, and a completed task is not overwritten as timed out.

Upgrade: replace the bridge add-in folder and the `revit-cli.exe` client together. `execute_raw` scripts are unchanged. The Abstractions NuGet bumps in lockstep to 2.0.2.
