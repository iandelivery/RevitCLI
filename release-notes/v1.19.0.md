### Highlights

- **Raw execution on by default.** Every installed bridge now ships `allow_raw_execution: true` — the `configure setup` installer, local builds, and release artifacts all write the enabled default (previously the C# default said enabled while every generated config disabled it). `raw-mode` still toggles it at runtime; the toggle stays in-memory, so a Revit restart resets to the config value.
- **Multi-instance auth just works.** A second bridge of the same Revit version auto-allocates the next port in the version's range, and the instance registry now carries each instance's `api_key` next to its port — the client authenticates against every running instance without re-running `configure setup`.
- **Clearer 401 errors.** Auth failures no longer surface as "Unknown command": the client prints the URL plus the matching remedy (no key sent → run `configure setup`; key sent and refused → re-sync the rotated config; old bridge that publishes no key → restart Revit after an add-in update) and exits with code 2.
- **Docs.** Install and skill-install examples no longer `cd` to a fixed `C:\revit-cli` path, and every doc claiming the raw-mode default now agrees with the code.

Upgrade: replace your install folder, re-run `revit-cli.exe configure setup`, and refresh existing skill installs with `revit-cli.exe skill update`. Already-installed bridges keep their current `allow_raw_execution` value — flip with `revit-cli.exe raw-mode --enable` or re-run `configure setup` to adopt the new default.
